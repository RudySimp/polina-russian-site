# Инструкции запуска для Codex

Рабочий каталог: `/workspace/polina-russian-site`. Облачная задача уже изолирована. Используйте существующий checkout; не создавайте Git worktree без явного запроса пользователя. Сохраняйте имеющиеся изменения. Основная разработка сайта приостановлена по заданию пользователя до публикации среды.

## Сохранённые файлы и процессы

В snapshot должны войти checkout, node_modules, .env и .local с локальными демоучётными данными. Не печатайте их значения. Процессы Next.js и PostgreSQL после восстановления запускаются заново. Сохранность Docker volume в новой задаче не проверена: при пустом volume миграции и seed воспроизводят демонстрационную БД. Нельзя утверждать, что данные пользователя восстановлены, без отдельной проверки.

## Подготовка

1. Перейдите в `/workspace/polina-russian-site`. Проверьте Node.js 24 (проверен 24.19.0), npm 11 (проверен 11.9.0), `docker info` и `docker compose version`.
2. Если зависимостей, БД или сборки нет, выполните `bash scripts/cloud-install.sh`. Скрипт с `set -eu` устанавливает по lock-файлу и должен завершиться ненулевым кодом при ошибке. Он не зависит от ФИПИ и «Решу».
3. При обычном запуске выполните `npm run db:up`, затем `npm run db:migrate`. Если локальная БД новая и DEMO_MODE=true, выполните `npm run seed`; повторный seed сохраняет существующие записи.
4. Next.js загружает `.env`. Нужны DATABASE_URL, POSTGRES_PASSWORD для локального Compose, APP_ORIGIN, DEMO_MODE и COOKIE_SECURE. `npm run setup:env` создаёт отсутствующий `.env` со случайным локальным паролем, существующий не меняет. APP_ORIGIN=http://localhost:3000 и COOKIE_SECURE=false допустимы только для локальной HTTP-разработки. При HTTPS используйте соответствующий Origin и COOKIE_SECURE=true. Никогда не копируйте секреты в инструкции, Git или отчёт.

## Запуск и готовность

1. Выполните `npm run dev` в терминальной сессии из рабочего каталога; сохраните идентификатор сессии для остановки. Порт — 3000. Если порт занят, сначала выясните, принадлежит ли процесс текущей задаче; не завершайте чужие процессы.
2. Дождитесь сообщения Ready и выполните внутренний запрос `curl -i http://localhost:3000/api/me`. Ожидается 401 с JSON `Войдите в аккаунт.`. HTTP 500, отказ соединения и отсутствие ответа требуют диагностики логов и БД.
3. Выполните `node scripts/check-environment.mjs`: ожидаются 8 проверок, в том числе настоящий вход, чтение упражнений/ДЗ из PostgreSQL, отсутствие эталонов до сдачи, разграничение ролей и защита Origin. Скрипт использует только вымышленные аккаунты, удаляет созданные сессии, учебные данные не изменяет.
4. Не создавайте пользовательскую preview-ссылку на localhost. Пользовательских страниц сейчас нет: `/` возвращает 404. Это проверенная серверная основа, не готовый сайт. После разрешения продолжить разработку создаются страницы и продуктовые тесты отдельной задачей.

## Проверки и остановка

- `npm run typecheck`, `npm run lint`, `npm run build` должны завершаться успешно.
- `npm test` сейчас завершается кодом 1: `No test files found`. Unit-набор не реализован. Не называйте его прошедшим и не включайте passWithNoTests.
- Playwright установлен, но e2e-набор и UI отсутствуют; браузерный пользовательский сценарий пока неприменим.
- Для проверки production-сборки остановите только свой dev-сервер, выполните `npm run build`, затем `npm run start` и повторите `node scripts/check-environment.mjs`.
- Остановка Next.js — Ctrl+C в сохранённой сессии. В текущем облачном терминале Ctrl+C однажды завершил обёртку, сохранив дочерний Next.js: проверьте освобождение порта через `ss -ltnp '( sport = :3000 )'`. Если он занят, установите PID и рабочий каталог оставшихся процессов (например, через `ps` и `/proc/PID/cwd`) и отправьте `kill -TERM` только процессам Next.js/npm, которые вы сами запустили из этого checkout. Не используйте общий pkill. Остановка своей локальной БД — `docker compose stop db`. Не удаляйте volume.

## Ошибки зависимостей

- При недоступном Docker зафиксируйте ошибку: PostgreSQL обязателен для API. Если уже предоставлен внешний PostgreSQL 17, используйте его DATABASE_URL безопасно и выполните миграции; локальный db:up для него не нужен. Не запрашивайте пароль в чате и не создавайте фиктивную БД или секрет.
- При отсутствии файлов исходников не создавайте заново сайт: проверьте восстановление snapshot и подключение нужного репозитория. На момент настройки удалённый GitHub был пуст, локальный checkout без первого коммита. Установка из одной удалённой ветки main пока невоспроизводима; подготовленные файлы должны сохраняться в snapshot.
- Недоступность fipi.ru, doc.fipi.ru и sdamgia.ru не мешает этому workflow. Сетевую настройку образовательных источников пользователь отложил до публикации среды. Не обходите прокси и не отключайте TLS-проверку.

Публикацию среды выполняет продукт Codex Cloud. Сохранение этих инструкций не означает публикацию или подтверждённое восстановление в новой задаче.
