# Локальный импорт и разрешение публикации

Исходники не входят в Git или `apps/showcase/dist`. Папки `ЗАДАНИЯ ОГЭ И ЕГЭ`, `Русский ОГЭ 2027` и `private-materials` исключены из Git. Новые документы удобно помещать в первые две папки, включая вложенные каталоги. Перед добавлением других каталогов исключите их из Git. Не перемещайте исходники в `public`.

## Извлечение

```sh
npm ci
npm run content:import
node scripts/report-materials.mjs
```

В Windows с переносимым Node используйте `scripts/windows.ps1 content:import`. Команда рекурсивно перечисляет DOCX/DOC/PDF/TXT/MD/JSON/CSV/XLSX, исключая зависимости, сборки и собственные промежуточные результаты. DOCX разбирается как ZIP/XML с сохранением абзацев, таблиц, номеров и ссылок; PDF — постранично, с координатами текстового слоя. DOC/XLSX только инвентаризируются: для них нужен конвертер. Проектные текстовые файлы не объявляются учебными заданиями.

Результаты находятся в `private-materials/import`:

- `inventory.json`: имя, полный и относительный путь, формат, размер, ID, объём, извлечение, признаки содержания, права и проблемы.
- `<sourceId>.json`: абзацы и таблицы DOCX либо страницы и координаты PDF.
- `<sourceId>.txt`: текстовый слой PDF для локального анализа.
- `candidates.json`: условия, ответы, извлечённые разборы, номера и отпечатки кандидатов из DOCX.

Парсер каталогов ожидает существующую структуру «Вариант 001», условие, раздел решений и ключи. Новый документ иной структуры сначала извлекается, затем требует адаптера или ручного переноса в контентный JSON. PDF автоматически не превращается в опубликованный банк. Отсутствующий текстовый слой, колонки, рисунки и цветовые выделения сверяются визуально; OCR отдельно, после проверки необходимости. Ошибка чтения PDF завершает импорт с ненулевым кодом.

## Предметная и правовая проверка

Для каждого кандидата сверяйте полный контекст, все варианты, ключ, объяснение и границы правила. Указывайте экзамен, тему, навык, сложность и тип ошибки. Сравнивайте не только ключи документа: объяснение должно обосновывать каждый выбранный и отвергнутый вариант. Проверяйте точные дубли и группы похожих вариантов из отчёта.

Сторонний полный текст, изображение или таблица не разрешаются одним наличием файла на компьютере. Уточняйте происхождение и права. В текущей подборке разрешены оригинальные варианты, прямо обозначенные в предоставленных каталогах и выбранные по поручению владельца проекта. Внешние банки из реестров ссылок не копируются. ШКОЛКОВО и 100balnik зарегистрированы как справочная база/карантин. Авторство Полины не приписывается автоматически.

`content/review-manifest.json` — явный список `approved`. Добавьте запись с `candidateId`, неизменённым `fingerprint`, независимо проверенным `answer`, темой/навыком, уровнем, `rightsBasis`, датой и `reviewNote`. Укажите шаги, подсказку и необходимые `corrections` с точными `from`/`to`. Отпечаток фиксирует исходное условие; исправления применяются после его проверки. Предметное утверждение Полиной остаётся отдельным статусом `teacherApproval`, сейчас `pending`.

## Обновление банка

```sh
npm run content:publish-reviewed
npm run showcase:typecheck
npm test
npm run showcase:build
npm run test:e2e
```

Публикующий скрипт проверяет источник, объявленную оригинальность, отпечаток, ключ и обязательные поля. Он выпускает только разрешённые записи в `apps/showcase/src/content/exercises/*.json`. Исправленный исходник с другим отпечатком требует повторной проверки. Никогда не меняйте fingerprint только ради обхода отказа.

Теория оформляется отдельными JSON в `content/lessons` публичного приложения, используя типы `model.ts`: правила, примеры, таблицы, сравнения, алгоритмы, интерактивы, самопроверка и итог. Новая оригинальная практика также добавляется JSON-коллекцией; укажите источник и редакторский статус. `build-content-index.mjs` обнаруживает новые JSON, генерирует индекс и отдельные загрузки уроков. При добавлении новой темы внесите только её метаданные в `topics.ts`, не создавайте индивидуальную страницу.

`content:check` проверяет связи, уникальность, достаточный объём опубликованных тем, схемы блоков, ключи, позиции интерактивов, права и маршруты. Сборка проверяет отсутствие документов, закрытой инвентаризации и серверных данных. CI использует только проверенные JSON: исходные частные файлы для сборки не нужны. После обычного commit/push в main Actions проверяет и публикует Pages. После деплоя `node scripts/check-public.mjs` сверяет все маршруты и хеши текущей сборки.

Изменение условия или критериев требует повышения `revision`; старые локальные попытки другой версии не используются. Не публикуйте сразу весь извлечённый массив: структурно полный кандидат ещё не является проверенным заданием.

## Обновление центра ОГЭ

Редакторские проверки хранятся в oge-existing-corrections.json, oge-review-additions.json и oge-expansion-review.json. node scripts/merge-oge-review.mjs собирает 148 разрешённых импортов; затем запускаются publish-reviewed.mjs и build-content-index.mjs. Политика ответа берётся из oge/specification.json, а не выводится из сравнения номера.

Оригинальные тексты и задания: node scripts/build-oge-originals.mjs; уроки: node scripts/build-oge-lessons.mjs; тренажёры: node scripts/build-oge-activities.mjs. Для аудио сначала prepare-oge-summary.mjs, затем record-oge-audio.ps1 в Windows с Microsoft Irina Desktop ru-RU и register-oge-audio.mjs. Файлы уже включены в разрешённые публичные аудио; CI не требует голоса Windows. build-oge-variants.mjs фиксирует ссылки на проверенные версии заданий. После изменений нужны content:check, типы, тесты и сборка.

Дополнительная папка Учебники исключена из Git. Её PDF не разрешены к воспроизведению наличием на диске; один файл имеет нулевой размер. Эти книги отдельно инвентаризированы, их текст не выдан за проверенный импорт банка.
