## Безопасная обычная команда

`npm run content:publish-reviewed` остаётся штатной командой. Сам publisher теперь сначала проверяет все источники, редакции и допуски, а затем пишет только действительно изменённые коллекции. Он сохраняет порядок и полный текущий объект уже опубликованного задания, включая прежние исправления, sourceTextId, ruleElements, shortAnswerConstraints и publicationReview. Он не восстанавливает устаревшее условие из старого approval.

`content/import-publication-lock.json` фиксирует хеш одобрения и хеш опубликованного содержательного payload для 178 текущих импортов. Это механическая защита от потери исправлений, а не новое методическое утверждение. Производные skillIds/elements/ruleElements/rulePaths и неградирующая обратная связь не превращаются в новый экзаменационный ключ.

Изменённое одобрение требует редакции выше текущей опубликованной и независимого publicationReview для этой редакции. Незаметное изменение текущего условия при той же редакции отклоняется. Снятое одобрение также не удаляет задания автоматически: для отзыва нужен отдельный явно проверенный перенос/удаление. Все эти проверки выполняются до записи первой коллекции.

Новые импорты требуют отдельного текущего редакционного допуска; известный старый id или скопированный допуск другой редакции его не заменяют. Для №2–3 publisher переносит approved.sourceTextId; при наличии общего SourceText дублирующий встроенный text удаляется только при подготовке новой опубликованной редакции. Уже сохранённые работы не меняются.
