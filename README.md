# Сайт Полины — рабочая среда

Репозиторий: `RudySimp/polina-russian-site`.

## Текущее состояние

В этой облачной сессии создана серверная основа будущей платформы. По уточнённому заданию основная разработка остановлена до публикации среды. Пользовательских страниц и готового сайта ещё нет: запрос `/` возвращает 404. Работает маршрут `/api/[...path]`. Код находится в рабочем каталоге; отправка на GitHub не выполнялась. Удалённый репозиторий на момент настройки не имел коммитов и веток, включая `main`; локальная ветка `work` — без первого коммита.

Есть модели пользователей, сессий, принадлежности учеников преподавателю, тем, уроков, упражнений, версий контента, назначений, попыток, приглашений и уведомлений; серверные операции входа, чтения, назначения и проверки. Это промежуточная разработка, а не завершённый MVP. Сквозной сценарий назначения и сдачи пока не принят тестами.

## Проверенная цепочка инструментов

- Node.js 24.19.0, npm 11.9.0, Git 2.52.0.
- Next.js 16.4.0, React 19.3.0, TypeScript 5.9.3.
- PostgreSQL 17 в Docker, Drizzle ORM 0.45.4, `pg`, Zod.
- Argon2id для паролей; сессии хранятся в PostgreSQL, cookie — HttpOnly/SameSite.
- ESLint; Vitest и Playwright установлены, но их тестовые наборы пока не созданы.

Установка воспроизводится по `package-lock.json`. Не запускайте параллельно npm/yarn/pnpm. Точные транзитивные версии определяет lock-файл.

## Запуск с нуля

Нужны Node.js 24, npm 11 и работающий Docker с Compose v2.

```sh
cd /workspace/polina-russian-site
bash scripts/cloud-install.sh
npm run dev
```

Полный скрипт устанавливает зависимости через `npm ci`, создаёт локальный `.env` только при его отсутствии, запускает PostgreSQL, применяет миграции, добавляет демоданные, запускает typecheck, lint и build. Существующие `.env`, записи БД и пароли не перезаписываются seed-скриптом.

Команды для обычного повторного запуска:

```sh
cd /workspace/polina-russian-site
npm run db:up
npm run db:migrate
npm run dev
```

Сервер слушает порт 3000. Для внутренней проверки используйте:

```sh
curl -i http://localhost:3000/api/me
node scripts/check-environment.mjs
```

Без сессии `/api/me` должен вернуть **401** с JSON `Войдите в аккаунт.` Это ожидаемая защита, а не ошибка запуска. Скрипт проверки затем входит через настоящие демоаккаунты, читает упражнения и ДЗ из PostgreSQL, проверяет отсутствие эталонных ответов, запрет чужого ДЗ и запрет запросов с постороннего Origin. Он удаляет созданные им сессии и не изменяет учебный контент или домашние задания.

Остановка сервера: Ctrl+C в запустившей его терминальной сессии, затем проверка освобождения порта. Если облачный терминал оставил дочерний процесс, завершите только собственные подтверждённые PID, как описано в [инструкции запуска](docs/ЗАПУСК_СРЕДЫ.md). PostgreSQL: `docker compose stop db`. Не используйте `docker compose down -v`: это удаляет данные БД. Процессы после восстановления облачной среды требуется запускать заново.

## Переменные окружения

См. `.env.example`. Команда `npm run setup:env` генерирует случайный локальный пароль БД и сохраняет `.env` с правами 0600; файл исключён из Git.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Подключение приложения к PostgreSQL; содержит секретный пароль, только в локальном `.env` или защищённой конфигурации. |
| `POSTGRES_PASSWORD` | Пароль локального контейнера PostgreSQL; генерируется одновременно с `DATABASE_URL`. |
| `APP_ORIGIN` | Разрешённый источник изменяющих HTTP-запросов. Для локальной разработки `http://localhost:3000`. |
| `DEMO_MODE` | `true` разрешает локальные вымышленные аккаунты и непроверенные демоматериалы; для реальной эксплуатации должен быть выключен. |
| `COOKIE_SECURE` | Для локального HTTP — `false`; при HTTPS должен быть `true`. |

Отдельные облачные секреты и API-ключи для этой настройки не требуются. Не включайте реальные данные детей. Правовые документы, инфраструктура и методическая проверка для реальной эксплуатации ещё не подготовлены.

Если Docker недоступен, база является обязательной зависимостью существующего API. Укажите уже предоставленный рабочий PostgreSQL 17 в `DATABASE_URL` через защищённую конфигурацию и выполните `npm run db:migrate`; не считайте HTTP 500 допустимым деморежимом. Команда `db:up` относится только к локальному Docker. Сетевые пароли не вводятся в чат и не коммитятся.

## Демоданные

Seed создаёт 3 вымышленных аккаунта (`polina.demo`, `sasha.demo`, `mira.demo`), 3 демонстрационных урока, 12 оригинальных упражнений и демоисторию. Случайные локальные пароли записаны в `.local/demo-credentials.json` с правами 0600. Файл исключён из Git; не публикуйте его содержимое. Повторный seed не должен дублировать или обновлять существующие материалы.

Данные находятся в Docker volume `polina-russian-site_polina-postgres`. Сохранность внешнего Docker volume после публикации/восстановления облачной среды не проверена. В свежем volume миграции и seed воспроизводят демонабор. Для сохранения пользовательских данных нужен отдельный проверенный процесс резервного копирования; сейчас используется только демонстрационный набор.

## Проверки качества

```sh
npm run typecheck
npm run lint
npm run build
node scripts/check-environment.mjs
```

`npm test` запускает Vitest, но сейчас завершается кодом 1: `No test files found`. Это отсутствие реализованных unit-тестов, а не прошедший набор. Не добавляйте `--passWithNoTests` для сокрытия этого состояния. `npm run test:e2e` также предназначен для будущего набора; UI ещё не создан.

Результаты текущей проверки и инструкции публикации: [docs/НАСТРОЙКА_СРЕДЫ.md](docs/НАСТРОЙКА_СРЕДЫ.md). Доступность внешних источников: [docs/ИСТОЧНИКИ_И_АКТУАЛЬНОСТЬ.md](docs/ИСТОЧНИКИ_И_АКТУАЛЬНОСТЬ.md).
